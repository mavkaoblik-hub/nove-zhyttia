# Security / threat model

Trust roots: existing pinned SSH host key + owner key, WG keys, owner Git review, local Windows user, trusted Blender/Godot binaries. The bridge does not sandbox Python/GDScript. Local approval is required before code-bearing staging is opened by Godot or any render runs. New Blender scripts require offline local allowlisting by exact revision/hash plus exact-job confirmation.

Each request binds method, exact URL path, Unix timestamp, 128-bit random nonce and SHA-256 body using HMAC-SHA256. Clock skew <=60 seconds. Nonces persist in SQLite 120 seconds. Keys have 30-day validity, role/device scope, hot revocation from credentials file. Never send them through GitHub. Owner key remains root-readable; device key is emitted only into installer SSH pipe, persisted as user-bound DPAPI XML under user-only ACL. Same-user malware and VM root can defeat these protections.

Private socket allows peer .2 and VM .1 only; selected transport is SSH forwarding so effective client is VM .1. systemd IP filter also permits VM .1 for owner CLI. WG encrypts packets; public routing is forbidden. Max 20 connections/sec, 8 concurrent requests, 15-second socket timeout, 12 MiB request, 8 MiB artifact, 256 MiB total artifact metadata quota, 100 outstanding jobs; 256 MiB/50% CPU server limits. Files immutable; no generic filesystem API. Names do not accept slash, colon, traversal. State directory writable only by bridge account/root. Job args/credentials never logged by HTTP handler.

Windows: path canonicalization plus ancestor reparse checks, no remote shell, no program installation, no registry/firewall edits. STOP file and device revocation; timeout and memory checks; foreground process; process kill targets tool PID. This is NOT a Windows Job Object sandbox: descendant processes, arbitrary trusted-tool code and asynchronous stdout buffering are residual risks. Do not approve untrusted project scripts. Timeout default 120 sec, memory 4096 MiB, minimum free disk 2 GiB; snapshots capped at 1 GiB. Scene inspection opens only approved staged .blend files with autoexec disabled; trust scene dependencies because external asset loading is not OS-sandboxed.

Approval hashes bind exact local receipt bytes. Source-to-staging copies are local snapshots with a SHA manifest, not a verified Git tree; source must be quiescent during copy. V0.2 is never modified. No source promotion is implemented. Staging outputs should be manually reviewed before production import.

Retention: quotas stop uploads when full. Automatic pruning/backup scheduling not enabled. Owner must back up and clear reviewed terminal job data offline; do not blindly delete while gateway runs. Audit contains actor/action identity/status; job body contains args/revision; do not include secrets in arguments. Local install hash trust anchor is delivered independently in README/release message, not downloaded and trusted from the same endpoint.

Missing end-to-end proof and disabled actions are explicit acceptance blockers, not waived requirements.
